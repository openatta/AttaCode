# `/btw` 侧问 需求规格

**目标：** 让用户在不打断当前 turn、不污染主对话上下文的前提下，就"这次会话里已经发生过的事"问一句题外话，答案显示在一个独占的半屏区域里，看完即走。

**背景：** 这是 Claude Code 的 `/btw`（by the way）功能，我们学习它。CC 的官方规格见
<https://code.claude.com/docs/en/interactive-mode> 的 "Side questions with /btw" 一节，本文
第二章把它的行为规格抄成了对照表 —— **抄的是行为，不是布局**：CC 用的是一个可关闭的浮层，
我们要的是一个把转录区压到一半、盖住下半屏的独占区域（见第三章，这是本项目自己的决定）。

**状态：已实现**（`crates/bridge/src/btw.rs` + `crates/tui/src/regions/btw.rs`）。
第五章那条"拿不到上下文"的结论**是错的**，正门一直都在，见该章的更正。

---

## 一、范围

- **In scope**
  - `/btw <问题>` 提交后，在一个独占区域里显示一次性的回答
  - `/btw` 不带问题 = 重新打开该区域，停在最近一次问答上
  - **turn 正在跑的时候也能用**，且不打断它
  - 该区域自己的键盘契约：滚动、翻看早前问答、退出、清空
  - 该区域的布局契约：转录区压到约一半，它占下半屏并盖住状态区/输入区/底栏/子代理条
  - 问答**不进入主对话历史**，不占用主上下文
  - 早前问答只在本次进程内存活，退出即散

- **Out of scope**
  - 侧问里的多轮追问（CC 明确是单次回答；要继续就再问一次）
  - 侧问里的工具调用（见第二章"无工具"）
  - CC 的 `f` 键（把侧问 fork 成后台子代理）—— 依赖我们尚未接的子代理 fork 能力，单列
  - CC 的 `c` 键（复制为原始 Markdown）—— 依赖剪贴板，可选，见第六章
  - VS Code 扩展那种"面板里继续追问"的形态

- **前置依赖**
  - 无。第五章原来写的那条 AttaCore 缺口是误判，正门一直都在。

## 二、行为规格（对照 CC）

| # | 规则 | 说明 |
|---|---|---|
| B1 | **只从已有上下文回答** | 用户消息、模型回复、已经拿到的工具结果。可以问"你刚才读的那个文件叫什么"，不能问"去看看 X 文件" |
| B2 | **无工具** | 不读文件、不跑命令、不搜索、不上网。够不着的东西就说够不着 |
| B3 | **turn 跑着也能用** | 侧问独立跑，不打断主 turn。它看得见此刻为止的一切，**除了模型正在写的那条回复** |
| B4 | **单次回答** | 区域里没有追问。要继续就再 `/btw` 一次。退出侧问区 = 不要这一问了：在途那次调用当场断开，答到一半的话一个字都不留（半截答案进了早前问答，下一问会把它当上下文带上去，而它是一句没说完的话） |
| B5 | **不进历史** | 问和答都不进主对话，不占主上下文 |
| B6 | **能看见早前问答** | 最近 5 条以暗色列在当前回答上方，更早的只报个数 |
| B7 | **侧问看得见侧问** | 每次提问把最近 20 条侧问问答一起带上，直到用户清空 |
| B8 | **只活在本次进程** | 不落盘。退出 AttaCode 就没了 |
| B9 | **便宜** | 主对话的 prompt cache 是热的时候，一次侧问的成本≈答案本身 |

> B3 和第三章的布局有冲突，见第四章 Q1。**已定：照 CC，接受盖住期间看不见主任务进度。**

## 三、区域契约

新增一个区域，规范名（体例见 `docs/TUI_DESIGN.md`）：

| 代码路径 | English | 中文 |
|---|---|---|
| `btw` | Side Question | 侧问区 |

### 布局

激活时：

```
┌───────────────────────────────┐
│ transcript   转录区            │  ← 压到约屏幕的 1/2
│                               │
├───────────────────────────────┤
│ btw          侧问区            │  ← 占下半屏，盖住
│  ┌─────────────────────────┐  │     operation_status / composer /
│  │ 早前问答（暗色，最多 5 条）│  │     footer_hints / sub_agent_bar
│  │ ─────────────────────── │  │
│  │ 当前问题                 │  │
│  │ 当前回答（可滚动）        │  │
│  ├─────────────────────────┤  │
│  │ btw 自己的状态栏          │  │  ← ↑↓ 滚动 · ←→ 翻看 · x 清空 · Esc 退出
│  └─────────────────────────┘  │
└───────────────────────────────┘
```

- **独占。** 侧问区在最上层，激活期间键盘全归它，主 UI 的任何操作都做不了。
- **不参与主堆叠。** 它和 `overlay` 是同一类东西（盖在上面、一次一个），区别是
  `overlay` 是全帧的，`btw` 只吃下半屏、上半屏仍然是转录区。
- **自带状态栏。** 因为它盖住了底栏，用户在这期间没有别的地方可以看见"现在能按什么"。
  这一行至少要说清楚：滚动、翻看早前、清空、退出。
- **有请求在等的时候，这条线先说那件事**（盖过上面那几条，流式期间也说）。见下面
  "为什么审批不算在 (a) 里面"。

### 键盘契约（照抄 CC，去掉两条依赖外部能力的）

| 键 | 行为 |
|---|---|
| `Esc` / `Enter` / `Space` | 退出侧问区，回主 UI；**在途那一问就地作废**（见 B4） |
| `↑` / `↓` | 滚动当前回答 |
| `←` / `→` | 在早前问答之间翻（`←` 往旧，`→` 往新） |
| `x` | 清空早前问答列表 |
| ~~`c`~~ | 复制为原始 Markdown —— 可选，见第六章 |
| ~~`f`~~ | fork 成后台子代理 —— out of scope |

## 四、必须拍板的问题

**Q1（最要紧）：turn 跑着的时候，侧问区盖住了状态区和子代理条，用户就看不见 spinner、
耗时、子代理进度了。** —— **已定：照 (a)**，跟 CC 一致。CC 也是这样，那是这个形态的
代价，不是遗漏。下面三条选项留作记录。

而 B3 明说侧问最有用的场景恰恰就是"turn 跑着的时候"。三条路：

- **(a)** 照当前布局做，接受这段时间看不见主任务进度。最简单，但把 `/btw` 最有价值的
  场景做成了"用的时候是瞎的"。
- **(b)** 侧问区自己的状态栏上捎带一小段主任务状态（spinner + 秒数 + 子代理数）。
  多几行代码，`FrameState` 里那些数据现成就有。
- **(c)** 只盖 `composer` 和 `footer_hints`，让 `operation_status` 和 `sub_agent_bar`
  留在屏幕上。改动最小，但会把侧问区挤成不规则的形状。

当时倾向 (b)，最终定 **(a)** —— 跟 CC 保持一致。要改成 (b) 的话，数据在
`FrameState` 里现成，加在侧问区自己那条状态栏上即可。

**Q2：`/btw` 提交时 turn 没在跑，还允许吗？** —— **已定：允许**，和 CC 一致。

**Q3：侧问用哪个模型？** 主模型最准但最贵；小模型便宜但可能答不准"你刚才为什么那么做"。
CC 没说。**已定：用主模型**（B9 说了 cache 热的时候很便宜）。要做成可配置的另说。

**Q4：答案是流式出还是等全了再显示？** —— **已定：流式**，等待期间显示“想一下……”。

## 五、上下文从哪儿来（本章原结论是错的）

**原来写的是**：侧问拿不到会话上下文，因为 `Agent` 的 `session: SessionManager` 是
`pub(crate)`，而 `Agent` 已经被 move 进 `run()`；三条路里只有"改 AttaCore"可行，所以
本需求不进入实施。

**这个结论是错的**，漏了一条正门：

`ModelInterceptor::on_request`（`Builder::model_interceptor`，扩展点 `model.request`）在
**每次模型调用发出之前**把整个 `ModelRequestView` 交到手上 —— prompt blocks、messages、
params 全在里面。那就是模型此刻看见的东西，一个字不差，而且每次调用都刷新。

它还顺带把 B3 那句"它看得见此刻为止的一切，**除了模型正在写的那条回复**"实现得分毫不差：
最后一次出站请求的内容，恰好就是"到这一刻为止、不含还没写完的回复"。

所以**不需要改 AttaCore**。实现见 `crates/bridge/src/btw.rs` 的 `ContextMirror`
——它只抄不改（`on_request` 允许改，但改了主对话的请求就不再是"不打扰主 turn"了）。

原来那三条路里的另外两条仍然不该走，理由不变：从 `AgentEvent` 攒影子副本，攒出来的是
**渲染投影**（没有 system prompt、工具入参被摘要过）；读会话 jsonl 内容是真的，但当前
这一轮还没落盘，正好错过侧问最有用的那段。

### 侧问是怎么发出去的

拿到上下文之后直接调 `Arc<dyn Model>`：

- `tools` 传**空表** —— B2 那条"无工具"的落点。不给工具定义，模型就没法调工具。
- `prompt_blocks` **原样带主对话的** —— 改一个字都会让整段 cache 前缀失效，B9 的"便宜"
  就是这么来的。所以"这是道侧问"写在最后那条 user 消息里，不塞进 system prompt。
- `thinking_mode` 关掉 —— 一次性短问答，extended thinking 只会让用户多等。
- 侧问跑在**自己的 task 上**，`dispatch` 不 await 它 —— 这是 B3"不打断主 turn"的落点。

## 六、验收

激活与退出：

- [ ] `/btw 这个函数返回什么` → 转录区压到约一半，侧问区出现在下半屏
- [ ] 侧问区激活期间，主 UI 的键（提交、滚动转录、切换模型…）一律无效
- [ ] `Esc` / `Enter` / `Space` 退出，主 UI 完整恢复（草稿、滚动位置都还在）
- [ ] `/btw` 不带问题 → 重新打开，停在最近一次问答上

行为：

- [ ] turn 跑着的时候 `/btw` → 主 turn **不被打断**，转录区照常在长
- [ ] 侧问的问和答**不出现在转录区**，`/cost` 的主上下文用量不因它上涨
- [ ] 问一个只有工具才答得出的问题（"看看 src 下有几个文件"）→ 明确说自己没有工具，
      而不是编一个数出来
- [ ] 连问三次 → 早前两条以暗色列在上方
- [ ] `x` 清空早前列表；退出 AttaCode 再进来，早前问答不在了
- [ ] 问一句长的，答到一半按 `Esc` → 那次请求当场断开（不再计费、不进早前问答），
      再 `/btw` 空参翻不到它

已定按 (a)，所以“看得见主任务进度”**不验** —— 盖住期间看不见是预期行为。

### 为什么审批不算在 (a) 里面

(a) 让渡的是"看得见进度"。**等人答的请求不是进度，是一个停住的主 turn。**
权限审批（和模型的 `AskUserQuestion`）在侧问区期间既看不见也答不了，而引擎那头
不是在跑，是停在 `runtime::turn` 的那个 `select!` 上等答案——
`execution.permission_prompt_timeout_secs` 默认 300 秒，超时按"未作答不是同意"
**拒掉**。用户看到的是"主任务怎么不动了"，五分钟后拿到一次被拒的工具调用，而他
从头到尾没见过那个框。

所以状态栏要说出"外面有 N 个在等你答"。**只是说，不是在这儿答**——真要答还是得
先退出去，侧问区里不开第二个对话框（那会把"一次一个模式"这条也破掉）。

- [ ] 侧问区开着时来一个权限审批 → 侧问区状态栏出现"外面有 1 个请求在等你答"，
      退出去之后那个框还在、答得了
